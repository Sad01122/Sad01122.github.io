The Big Idea: Logic Before Syntax

Programming starts before the first line of code. You must understand the problem, plan precise steps, then translate them into C++.

🎯 Problem→ 📥 Inputs→ 🧠 Steps→ 📤 Output→ 🔎 Check
💡
Quick tip: Explain your algorithm out loud for a simple task like "making tea". If a step is vague ("add some water"), your algorithm is not precise enough yet.

Algorithms & Flowcharts

An algorithm is a finite, ordered and unambiguous sequence of steps for solving a problem. It needs: defined task → known input → precise steps → termination → output.

⚠️
"Keep checking the log until it looks safe" is NOT a valid algorithmic instruction — "looks safe" is ambiguous and the stopping rule is unclear. Use measurable conditions instead.

Your First C++ Program

// Hello, Cyber Security! #include <iostream> using namespace std; int main() { cout << "Hello, Cyber Security!"; return 0; }
  • #include <iostream> → request a header (handled before compilation)
  • using namespace std; → skip writing std:: everywhere
  • main() → where execution begins; { } → a block; ; → ends statements
  • cout << → send to output; return 0; → normal completion

Compilation pipeline

1 · Source (.cpp)→ 2 · Preprocess→ 3 · Compile→ 4 · Link→ 5 · Executable
❓
Classic exam question: Does the CPU execute cout << "Hello"; directly? No — the CPU runs generated machine instructions, never the C++ text itself.

Input · Process · Output

The simplest execution model: Input data enters → Process transforms it → Output result leaves. cin >> reads into a variable, cout << sends it out. Don't confuse << with "less than" — meaning depends on context.

Arithmetic & Precedence

🎬 Worked Example — Trace the expression

🧩 int result = 10 + 3 * 2; then double d = 7 / 2;
1Look for operators: + and * both present — precedence decides the order, not reading order.
2* beats +: first compute 3 * 2 = 6.
3Then add: 10 + 6 = 16 → result holds 16 (not 26!).
4Next line — integer division: 7 / 2 → both operands are int → result 3 (decimal chopped, never rounded).
5Fix it: double d = 7 / 2; still gives 3! You must touch a double inside the math: 7 / 2.0 or (double)7 / 2 → 3.5.
6Exam habit: circle the operators, mark precedence, evaluate left→right within a level, then check operand types.

Overflow & Underflow — Two Counter Demos

Mechanical odometer model — n-digit counter wraps like a tally wheel
  • Overflow: result exceeds the type's maximum → wrong/unexpected value. Underflow: falls below the minimum (floats also lose precision).
  • N bits → 2ᴺ patterns: uint8_t = 0–255 (0…2ⁿ−1) · int8_t = −128…127 (−2ⁿ⁻¹…2ⁿ⁻¹−1)
  • Unsigned wraps (defined): uint8_t x = 255; x = x + 1; → 0 (mod 2ᴺ)
  • Signed overflow = undefined behavior in C++ — the demo's wrap-around is a two's-complement teaching model, not a guarantee
  • Fixed-width types (int8_t, uint32_t…) make bits explicit; check limits with <limits>: numeric_limits<int8_t>::min()/max()
🔐
Cyber link: type limits explain input-validation and memory-safety bugs — attempts, flags, scores and usernames must be stored with the right type.

🧠 Memory Tricks

  • << out, >> in — arrows follow the data stream. cout = stream out, cin = stream in.
  • = pours, == compares — assignment is an update, equality is a question (Week 3 preview).
  • int ÷ int stays int — 5/2 = 2; make one operand double (×1.0) to get 2.5.
  • Precedence ladder: () → * / % → + −.
  • static_cast = chop, not round — 9.8 → 9, 4.9 → 4.
  • Odometer wrap: 9999+1 → 0000 — that is overflow, visualized.
  • 8 bits = 256 patterns (2⁸): unsigned 0–255, signed −128…127.
  • Debug loop: Observe → Trace → Hypothesize → Fix → Retest ("OTHFR").

Week 3 — Decisions: if, else & Logic

Programs stop being straight lines. A decision picks a branch at run time based on a condition that evaluates to true or false.

⚠️
= vs ==: single = stores a value; == asks if two values are equal. Using = in an if is a classic bug (and usually a compiler error).

if · if-else · nested · else-if ladder

🪤

🧠 Memory Tricks

  • if = red light test — green: run the block · red: skip past it.
  • else = the other shoe — it only drops when the if didn't.
  • && needs BOTH checks, || needs EITHER — "honey, are you and home?" vs "pizza or burger?"
  • ! = mirror — true becomes false, false becomes true.
  • Strictest first — once a high score matches, lower thresholds can't be reached; ladder keeps order.
  • break = STOP sign — fall-through is the broken sign.
  • = pours, == compares — assign vs ask.
  • ?: = mini if-else — condition ? true-part : false-part.

Why Loops? — Controlled Repetition

Copying the same statement again and again makes code long, mistake-prone and painful to change. A loop writes the logic once and repeats it under a condition.

The cycle of every loop — check, do, change
  • Iteration: one round of the loop body · Counter: variable tracking repetitions · Update: changing it so the loop can end.
  • Increment ++ / Decrement --: add 1 / subtract 1.
  • A loop must always move toward "false" — otherwise it never ends.

while — Condition First (pre-test)

int i = 1; while (i <= 5) { cout << i << " "; i++; // update MUST exist inside the body }
StepConditionAction
i = 11 ≤ 5 trueprint 1 → i becomes 2
i = 22 ≤ 5 trueprint 2 → i becomes 3
i = 3..5true each timeprint 3, 4, 5
i = 66 ≤ 5 falseloop stops → output 1 2 3 4 5
⚠️
Infinite loop — the classic bug: forgetting i++ means the condition stays true forever (hamster on a wheel). Fix: update inside the body. Also note pre-test means 0 runs are possible: while (x > 5) starting at 5 never runs.
// Input validation: keep asking while the coupon is wrong string coupon; cin >> coupon; while (coupon != "SAVE10") { cout << "Invalid. Try again: "; cin >> coupon; }

Sentinel-Controlled Loops

Sentinel: a special value (e.g. -1) that does not represent normal data — it just tells the program "stop reading".

int number, sum = 0; cin >> number; // 1. read BEFORE the loop while (number != -1) { sum = sum + number; // 3. process only real data cin >> number; // 4. read AGAIN inside (missing = infinite loop) } cout << sum; // sentinel is NOT added
✅
Trace inputs 5, 8, 2, −1 → sum 5 → 13 → 15 → stop at −1 → output 15. The sentinel is a control value, not data — never include it in totals. Algorithm: read first · loop while ≠ sentinel · process · read next inside.

Nested Loops — Rows Outside, Columns Inside

for (int row = 1; row <= 3; row++) { // outer: 3 rows for (int col = 1; col <= 4; col++) { // inner: 4 columns per row cout << "* "; } cout << endl; // each row ends with endl }
  • 3 rows × 4 columns = 12 inner executions → 3 lines of 4 stars (total work = rows × columns).
  • Triangle pattern: inner limit follows the row — col <= row → *, **, ***.
  • Chessboard/grids: outer = row, inner = column, an if inside decides the square.

Division of labour: the loop decides whether to continue · the if decides what to do with this value · counter variables can count events (if (event == "FAIL") failed++;).

🧠 Memory Tricks

  • while = "while true, keep going" — condition first, may run 0 times. do-while = "do it, then ask" — runs at least once (don't forget the ;).
  • Loop cycle: condition → body → update → repeat — "check, do, change".
  • Missing update = hamster on a wheel — running, going nowhere → infinite loop.
  • Sentinel = stop sign, not data — -1 ends the sum, never joins it. Read-before, read-inside — the two reads of a sentinel loop.
  • Nested = rows outside, columns inside — total = rows × columns.
  • < vs <=: i < 5 stops at 4 · i <= 5 stops at 5 — "off by one".
  • Selection one-liner: count known → for · must show once → do-while · only condition → while · special stop → sentinel.

Why Functions? One Task, One Name

Copying the same block into five places means five places to fix when something changes. A function names one task, writes it once, and lets you call it whenever needed. Think of a recipe card: same procedure, different ingredients each time.

🎯 Problem→ 🧩 Decompose→ 🏷️ Name a task→ 📥 Parameters→ 📤 Return
A call jumps into the function — return jumps back
❓
Exam trap: defining a function does not run it. A perfect showWelcome() definition with no call prints nothing — execution starts at main() and only a call enters another function.

Anatomy: Prototype · Call · Definition

int square(int n); // 1. prototype — announces it (semicolon, no body) int main() { cout << square(5); // 2. call — executes it return 0; } int square(int n) { // 3. definition — the actual body return n * n; }

Parameters, Arguments & the Call Stack

Argument = the value sent by the caller. Parameter = the receiving variable in the function header. They are matched by position, and every parameter needs a type.

void displaySum(int a, int b) { int sum = a + b; cout << "Sum = " << sum; } int main() { displaySum(4, 6); // 4 → a, 6 → b (copies) }

Stack rule: only the currently active function executes. The caller pauses; when the callee returns, its local variables are destroyed and control resumes in the caller.

Pass-by-Value — The Function Works on a Copy

C++ copies each argument into its parameter. Changing the parameter changes only the copy — the caller's original variable stays untouched.

void change(int n) { n = 100; // changes only the local copy } int main() { int x = 5; change(x); cout << x; // prints 5 — NOT 100 }

Default Arguments — Optional Values From the Right

void greet(string name, string title = "Student") { cout << "Hello " << title << " " << name; } greet("Ali"); // Hello Student Ali (default used) greet("Ali", "Mr."); // Hello Mr. Ali (caller overrides) int power(int base, int exp = 2); power(5); // base = 5, exp = 2 power(5, 3); // base = 5, exp = 3
⚠️
Right-side rule: once a parameter has a default, every parameter to its right must also have one. void f(int a = 1, int b); is illegal — the caller cannot skip b and still supply it.

Reference Parameters — Work on the Caller's Variable

Pass-by-value copies. Add & and the parameter becomes an alias for the caller's storage — writing through it writes through the original.

void add1(int &x) { // x refers to the caller's variable x++; } int main() { int num = 10; add1(num); // num becomes 11 } void swap(int &a, int &b) { int temp = a; a = b; b = temp; }

Recursion — Base Case + Smaller Step

A recursive function calls itself. It needs exactly two ideas: a base case that stops, and a recursive case that makes the problem smaller.

void countdown(int n) { if (n == 0) { // base case — stops cout << "Go!"; return; } cout << n << " "; countdown(n - 1); // recursive case — smaller n } // countdown(3) → 3 2 1 Go!
Descent goes deeper; the stack unwinds in reverse (LIFO)

↻ tap
A

Q6

exit() vs return?

↻ tap
A

exit() ends the whole program · return ends only the current function.

  • Static = local name, global life. Like a hotel room key that keeps the same room number forever.
  • & = same house, different door. a and x are two names for one storage.
  • Overload = same name, different signature. Never return type alone.
  • Recursion = base to stop + smaller step to get there + unwind to combine. No base → stack overflow.
