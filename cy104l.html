🎬 Worked Example — The hidden file mystery

🧩 You find nothing with dir — but the file "vanished"
1Symptom: a lab partner says secret.txt exists on the desktop, but your dir shows nothing.
2First check: run dir /a — if it appears, the file is only hidden (attribute), not deleted.
3Confirm the attribute: attrib secret.txt shows A H — the H bit explains it.
4Fix (unhide): attrib -h secret.txt → normal dir sees it again.
5Takeaway: attrib +h is cosmetic hiding, not security — dir /a sees straight through it. Attackers use this trick, so defenders must know it.

🧠 Memory Tricks

  • Internal vs external → Internal = Inside the shell (navigate files) · External = Executables on disk. Internals don't need a .exe — externals are their own programs.
  • PID chain → netstat -ano finds the PID → tasklist maps PID → name → taskkill ends it. "Find it, name it, kill it."
  • attrib signs → + = set (hide) · − = clear (unhide). Same trick for +r/-r read-only. Plus puts on, minus takes off.
  • Troubleshoot order → "IPTNT" — Ipconfig → Ping → Tracert → Netstat → sTart checking processes. Local config → reachability → route → connections.

⚠️
Requirements: 64-bit Windows PC with virtualization enabled (VT-x/AMD-V in BIOS), 16 GB RAM recommended (8 GB with one VM), ~150 GB free disk, admin access. Download all ISOs before class and verify: certutil -hashfile "file.iso" SHA256.

Install Pipeline — VMware → Windows → Kali → Snapshot

Lab 03 flow
  • Task Manager → CPU → Virtualization: Enabled (else BIOS: VT-x/AMD-V/SVM)
  • VMware: Typical → "I will install the OS later" → Windows 11 x64 → Windows_YourRegID
  • 80 GB split disk · 4 GB RAM · 2 cores · NAT · encryption + Add vTPM if prompted
  • Attach ISO → "Connect at power on" → boot → after first restart do NOT press a key
  • Custom install → pick the VM's unallocated disk (never the host disk!) → finish OOBE → VMware Tools
  • Kali: Debian 64-bit → Kali_YourRegID → 50 GB → Graphical install → Guided, one partition
  • Keep Xfce only → GRUB to /dev/sda → disconnect ISO → reboot → login
  • Run hostname whoami pwd ip -4 addr (not 127.0.0.1) + sudo apt update
  • Shut down both guests → take Clean_Install snapshots → screenshot evidence

🎬 Worked Example — "Which disk do I partition?"

🧩 The scariest screen in the Kali installer
1You're at "Partition disks." The installer lists two disks: your host's real drive and the ~50 GB VMware virtual disk.
2Wrong move: picking the host drive formats your real Windows — data gone. This is why the VM's disk is created separate and clearly sized.
3Correct move: choose Guided – use entire disk → select only the ~50 GB VMware disk (SCSI, matching the size you created).
4Then: "All files in one partition" → Finish partitioning → write changes → Yes. It formats inside the virtual disk — the host stays untouched.
5Viva follow-up: "Where does GRUB go?" → the main virtual disk (/dev/sda), not a single partition.

🧠 Memory Tricks

  • Host vs Guest → the Host hosts the party (your PC); the Guest visits (an OS inside a box). Type 2 hypervisor = runs on an OS, like an app.
  • Snapshot ≠ Backup → Snapshot = undo button · Backup = a separate copy elsewhere. Delete the VM files and snapshots die with them.
  • Specs ladder → Windows: 80 GB · Kali: 50 GB · RAM 4 GB each · 2 cores each · NAT both. "80-50, 4-2-NAT."
  • Kali install words → GFG: Guided → Files in one partition → GRUB on /dev/sda.

Task 02 — The Backup Test ✅

Part 1 — create & copy

  • mkdir Project → create 3 files with any content (echo '...' > file)
  • mkdir Backup → cp -r Project Backup/ (-r copies the whole folder)
  • Compare trees: ls -R Project Backup
Project (design/report/requirements) copied into Backup/ — both trees identical

Part 2 — delete & compare

  • rm Project/design.txt (destroy one original)
  • diff -r Project Backup/Project → reports Only in Backup/Project: design.txt
  • Backup still holds the file the original lost → PASSED
diff -r proves the backup kept design.txt after the original was deleted
🔍
Key command: diff -r Project Backup — recursively compares directories. Exit code 0 = identical · 1 = differences found · 2 = error.

🧠 Memory Tricks

  • cd vs ls → cd = go somewhere · ls = look around. Moving vs glancing.
  • mkdir vs touch → mkdir makes a doorway (folder) · touch makes a note (empty file). Folder, then file.
  • cp vs mv vs rm → cp = photocopy (original stays) · mv = physically move · rm = shred. Never rm -r before copying!
  • rm vs rmdir → rmdir eats only empty boxes · rm -r eats everything.
  • PID = process ID card number · kill <PID> tears up that card. kill -9 = "no negotiation".
  • grep = "globally regular expression print" — finds text inside files.
  • diff -r = "different recursively" — walks both trees, reports mismatches. The backup test.

🎯 Flip Cards — Lab 04 Viva (10 Qs)

Q1

What does pwd do?

↻ tap
A

Prints the current working directory — the full path of where you are (e.g. /home/sad/secret).

Q2

cd vs ls?

↻ tap
A

cd changes your location; ls lists the contents of where you already are.

Q3

mkdir vs touch?

↻ tap
A

mkdir creates a directory (folder); touch creates an empty file (or updates a timestamp).

Q4

cp vs mv?

↻ tap
A

cp makes a duplicate — original stays. mv relocates/renames — original path is gone.

Q5

rm vs rmdir?

↻ tap
A

rmdir deletes only an empty directory; rm deletes files, and rm -r deletes directories with everything inside.

Q6

What is grep used for?

↻ tap
A

Searches for a text/pattern inside files (or piped input) and prints matching lines.

Q7

What info does ps show?

↻ tap
A

Running processes: PID, user, CPU/memory use, and the command that started each one (ps ux).

Q8

What is a PID, and kill's role?

↻ tap
A

PID = Process ID (unique number of a running process). kill PID sends a termination signal; kill -9 forces it.

Q9

What does cat do?

↻ tap
A

Displays file content (cat file); with redirection (cat > file) it creates/writes content — used for the clue files.

Q10

Why diff -r in the Backup Test?

↻ tap
A

Recursively compares Project with Backup and reports missing/extra files — proving the backup still has design.txt after the original was deleted.
