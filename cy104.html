The Opening Problem — University Portal Incident

Ali gets an "urgent" LMS verification email, clicks, logs in — and later a stranger is inside his account: files viewed, profile changed, portal offline when he tries to report it. Goal of the lecture: explain what was attacked, which security property broke, and why one email caused all of it.

The CIA Model ⭐ (core of the course)

CIA triad — the three security properties
PropertyMeaningExample (Ali)ThreatControls
C — ConfidentialityOnly authorized people see itGrades visible only to youDisclosure / leakageAccess control, encryption, careful sharing
I — IntegrityAccurate & unmodifiedMarks must not change silentlyTampering, accidental changePermissions, validation, hashes, audit trails
A — AvailabilityReachable when neededLMS up at submission deadlineOutage, DoS, hardware failureBackups, redundancy, monitoring
❓
Class check: ransomware mainly threatens A (service unusable) — often C and I too. Quick-fire: file leaked → C · marks changed → I · portal offline → A.

Cyberspace, Cybersecurity & Data

  • Cyberspace — global interconnected environment: virtual · borderless · interactive · persistent. Users: individuals, organizations, governments.
  • Cybersecurity — ongoing effort to protect systems, networks, programs & data from unauthorized access, misuse, damage or disruption. Four verbs: Protect → Detect → Respond → Recover.
  • Cyberattack — intentional attempt to steal/expose/alter/disable/destroy/gain unauthorized access (attacker → action → impact).
  • Personal data — identity · contact · behavior · content; records: MED/EDU/JOB/FIN/DEV. Your day leaks data: unlock → Wi-Fi → LMS → maps → streaming.
  • Layered effort — People (awareness) + Process (policies) + Technology (tools). No single tool "solves" security.
⚠️
History: the change that made security hardest = connectivity. Stuxnet 2010 · Ukraine grid 2015 · Mirai 2016 · WannaCry 2017. 2025 numbers: 47.1M DDoS attacks (+121% YoY), 44% of breaches involved ransomware.

🎬 Worked Example — Which CIA property?

🧩 Step through: classify each impact
1Scenario: A phishing email steals a student password. The attacker logs in, reads private messages, edits the profile, then floods the portal with traffic.
2Asset first: credentials, private files, LMS account & service — identify what's valuable before naming the harm.
3"Reads private messages" → C. Confidentiality broken: unauthorized eyes saw data that was private.
4"Edits the profile" → I. Integrity broken: data changed without authorized update.
5"Floods the portal" → A. Availability broken: real users can't reach the service.
6Controls → People: awareness · Process: incident response · Technology: MFA, email filtering, monitoring. One attack, all three CIA letters hit!

🧠 Memory Tricks

  • CIA triad → ask "Can I Access?" — Confidentiality, Integrity, Availability. Viva favourite #1 — you'll use it every single lecture.
  • Four verbs → "Please Don't Ruin Recovery" — Protect, Detect, Respond, Recover. Defenders never "prevent" only — the cycle must end in recovery.
  • C vs I vs A → C = someone could read it · I = someone illlegally changed it · A = absolute silence (nobody can reach it). Ransomware = A + C + I, the full house.
  • National bodies (PK) → "Pakistan Networks Need Rescue" — PECA, NTISB, NR3C. Hotline: 9911.

Opening Problem — Shared Lab Account Incident

One shared admin password → fake update link → unknown file installed → logs deleted → confidential files online. Because everyone shared the account, nobody can say who did what. Lecture 2 answers this with: principles → AAA → risk terms → actors/vectors → frameworks.

Security Principles (decision rules)

Principles = reusable rules · Controls = the concrete way you apply them.

PrincipleOne-linerAsk yourself
Least privilegeOnly the access required — nothing moreSmallest permission set?
Defense in depthIndependent layers; one may failDoes this layer still work after another fails?
Secure defaultsNew thing starts with "deny"Safest practical config first?
Separation of dutiesSplit sensitive dutiesOne initiates · another approves · third audits
Fail securelyErrors must not grant accessDetect → Contain → Recover (no bypass!)
Minimize attack surfaceDelete unused accounts, services, ports, dataEvery feature = another misuse door
❓
Which principle is missing? Interns get admin → least privilege · One person creates and approves refunds → separation of duties · A DB error shows customer records → fail securely.

AAA — Authenticate · Authorize · Account

One request through three security gates
PartKey facts
AuthenticationClaim → Evidence → Decision. Factors: Know (password) · Have (phone/card) · Are (fingerprint) · Context · Recovery. Password + user PIN is NOT MFA (both knowledge).
AuthorizationSubject acts on Object via Action, per Policy. Models: DAC (owner), MAC (labels), RBAC (roles — university!), ABAC (attributes), rule-based. IDOR bug: /record/104 → /record/105.
AccountingCapture → Protect → Review logs. Answers Who/What/Where/When/Outcome.
🧠
Order trick: N before Z — Authenticate (who am I) → Authorize (what may I) → Account (log it). AAA = "Am I Allowed?"

Threat Actors, Attack Vectors & MITRE ATT&CK

  • Actors: Cybercriminal (money) · Insider (access/grievance/error) · Hacktivist (ideology) · Nation-state (strategy) · Opportunist (easy targets). Compare intent vs capability vs access vs resources.
  • Vectors (the route in): Human (phishing) · Application (web/API flaw) · Network (exposed service, rogue Wi-Fi) · Endpoint (malicious file/USB) · Supply chain (compromised update). Vector = route · technique = how they operate.
  • MITRE ATT&CK: shared language — tactics = why (goal), techniques = how (method). Chain: Initial Access → Execution → Credential Access → Collection → Impact.
  • Lab incident mapped: fake update link (initial access) → shared password (credential access) → file installed (execution) → files gathered (collection) → logs deleted & leak (impact).
✅
Incident solved: failed principles = least privilege + separation + secure defaults + accounting protection · failed AAA = shared secret / broad rights / no attribution · fix = individual accounts + MFA + least privilege + allow-listing + protected logs.

🎬 Worked Example — Diagnose the AAA failure

🧩 Match symptom → broken A, then fix it
A"A stolen password was accepted." → Authentication failed: evidence was forged/stolen.
AFix: add a second factor (Have: authenticator app) so one stolen secret isn't enough.
B"A student edits marks in another course." → Authorization failed: object ownership never checked (IDOR).
BFix: policy must verify subject↔object per action — RBAC + ownership check on every request.
C"An admin action has no log." → Accounting failed: no evidence, no investigation.
CFix: capture Who/What/Where/When/Outcome, protect logs from tampering, review them.

🧠 Memory Tricks

  • AAA order → N before Z: Authenticate → Authorize → Account. Login → permission → audit log. Never out of order.
  • 5 principles → "Least Depth Defaults, Separate, Fail" — Least privilege, Defense in depth, Secure defaults, Separation of duties, Fail securely.
  • Risk chain → A-V-T-A-I: Asset → Vector → Threat/Vulnerability → Attack → Impact. "The A-V train hits the T-A-I city."
  • Tactics vs techniques → tactics = Why (starts with W, goal), techniques = How (starts with H, method). ATT&CK: Initial access → Execution → Credential → Collection → Impact ("IE CCI").

Password + user-created PIN — is that MFA?

↻ tap
A

No! Both are knowledge factors — one stolen secret defeats both. Use password + authenticator app (knowledge + possession).

Q2

RBAC in one sentence?

↻ tap
A

Permissions follow job roles — students, teachers and admins each get their role's rights. The university example.

Q3

Vulnerability vs threat?

↻ tap
A

Vulnerability = exploitable weakness (the open window). Threat = the potential harm actor/event (the burglar).

Q4

Attack vector vs technique?

↻ tap
A

Vector = route into the target (phishing email). Technique = how they operate once there.

Q5

Tactics vs techniques in ATT&CK?

↻ tap
A

Tactics = why (attacker's goal, e.g. Initial Access). Techniques = how (the method used).

Q6

5 questions of useful accounting?

↻ tap
