Week 1 — 60-Second Summary

💡
Logic before syntax. A program = specific instructions + data that performs a task; a programming language = the notation used to write them. C++ is high-level → must be translated to machine code; the CPU never runs C++ text directly. Steps: Problem → Inputs → Processing → Output → Check.

First C++ Program & Compilation

#include <iostream> using namespace std; int main() { cout << "Hello, Cyber Security!"; return 0; }
  • #include <iostream> — makes cout/cin available
  • using namespace std; — write cout instead of std::cout
  • main() — entry point, execution starts here · { } — function body
  • cout << sends data out · return 0; = normal completion · ; ends statements
Compilation pipeline — source to executable
⚠️
<< is the stream insertion operator (send out), not "less than". >> reads whitespace-separated input into a variable.

Arithmetic, Precedence & Constants

OpOperationExample
+ - * /add/sub/mul/div8 + 2 → 10
%remainder (mod)8 % 3 → 2

Precedence (highest first): ( ) → * / % → + -. Worked: 20 - 6 / 2 * 3 → 6/2=3 → 3*3=9 → 20−9 = 11.

⚠️
Integer division: int ÷ int discards the fraction — 7 / 2 → 3. Use a double operand for decimals: 7.0 / 2 → 3.5.

Constants: typed const int MAX_ATTEMPTS = 3; (preferred, compiler blocks reassignment) · #define MAX_ATTEMPTS 3 (text replacement before compilation).

Style: meaningful names (failedAttempts ≫ x) · whitespace reveals structure · indentation follows blocks · useful comments — readable code is easier to audit (security link).

🎯 Week 1 — Likely Quiz Answers

Q1

Program vs programming language?

↻ tap
A

Program = specific instructions + data performing a task. Language = the formal notation used to write them (C++, Java, Python).

Q2

Stages: source → executable?

↻ tap
A

Source → Preprocess → Compile → Link → Executable. CPU never runs C++ text directly.

Q3

20 - 6 / 2 * 3 = ?

↻ tap
A

11 — / and * beat −: 6/2=3, 3×3=9, 20−9=11.

Q4

Why is user-name invalid?

↻ tap
A

Hyphen is treated as minus — identifiers allow only letters, digits and underscore (and no spaces).

Q5

Declaration vs initialization vs assignment?

↻ tap
A

Declare int a; create · Initialize int a = 3; first value at creation · Assign a = 4; replace later.

Week 2 — 60-Second Summary

💡
Store → Process → Trace. Variables are labelled memory boxes (int attempts = 3; = type + name + value). Expressions compute values under precedence rules. = stores (it is not equality). Conversion can silently truncate. Every type has limits → overflow/underflow. Hand tracing beats guessing when debugging.

Q1

Why int avg = 5 / 2; surprises?

↻ tap
A

Integer division gives 2, not 2.5 — the fraction is discarded before storing. Make an operand double.

Q2

Overflow vs underflow?

↻ tap
A

Overflow = exceeds the type's maximum (9999+1→0000) · underflow = below the minimum / float precision lost (0000−1→9999).

Q3

Implicit vs explicit conversion?

↻ tap
A

Implicit: double x = 5; (automatic) · Explicit: static_cast<int>(3.9) → 3 (you asked; truncates).

Q4

Syntax vs logic vs type error?

↻ tap
A

Syntax = grammar violated · logic = runs but wrong (total/2 with 3 quizzes) · type = wrong-type surprise (int avg = 7/2).

Week 3 — 60-Second Summary

💡
Decisions pick branches. A condition is true/false → C++ runs or skips a block. Master the four shapes (if / if-else / nested / else-if ladder), the three traps (order matters, dangling else, = vs ==), then && || !, ranges, flags, validation and switch.

🪤
Dangling else → binds to the nearest unmatched if; use braces. = vs == → if (x = 5) assigns (classic bug).

Logic, Ranges, Menus & switch

aba && ba || b!a
TTTTF
TFFTF
FTFTT
FFFFT
  • Range test: x >= 10 && x <= 90 — chained 10 <= x <= 90 does NOT work in C++
  • Short-circuit: && stops at first false · || stops at first true
  • Flag: a bool recording yes/no state (bool found = false;)
  • Validation: re-ask until legal (while (x < 1 || x > 6)) · menu: print → read → validate → act
  • switch: integral values only · case n: … break; — missing break = fall-through · default = no match
  • ?: cond ? a : b = one-line if-else · char 'A' vs string "A"
🧠
Ladder rule: in if (n<0) … else if (n==0) … else … an earlier branch can make later tests unreachable — test strictest first (90 before 80).
Q1

What does a missing break do?

↻ tap
A

Execution falls through into the next case — intended for grouped cases, a bug otherwise.

Q2

Which range test is correct for 10–90?

↻ tap
A

x >= 10 && x <= 90 — always AND between range ends (|| would match almost everything).

Q3

Dangling else?

↻ tap
A

An else binds to the nearest unmatched if — braces remove the ambiguity.

Q4

if/else-if vs switch?

↻ tap
A

if/else-if: ranges & complex conditions · switch: one integral variable vs exact values (needs break).
