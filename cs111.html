The Big Idea: Logic Before Syntax

Programming starts before the first line of code. You must understand the problem, plan precise steps, then translate them into C++.

🎯 Problem→ 📥 Inputs→ 🧠 Steps→ 📤 Output→ 🔎 Check
💡
Quick tip: Explain your algorithm out loud for a simple task like "making tea". If a step is vague ("add some water"), your algorithm is not precise enough yet.

Program vs Programming Language

TermMeaningExample
ProgramA specific set of instructions + data that performs one taskA program that reads two numbers and prints their sum
LanguageThe formal notation used to write instructionsC++, Java, Python

analogy: the recipe is the program; English/Urdu is the language it's written in.

Algorithms & Flowcharts

An algorithm is a finite, ordered and unambiguous sequence of steps for solving a problem. It needs: defined task → known input → precise steps → termination → output.

⚠️
"Keep checking the log until it looks safe" is NOT a valid algorithmic instruction — "looks safe" is ambiguous and the stopping rule is unclear. Use measurable conditions instead.

Four flowchart symbols every beginner must know

Why visualize first? Flowcharts make the sequence, processing and decisions visible so you can verify logic before fighting with syntax.

Your First C++ Program

// Hello, Cyber Security! #include <iostream> using namespace std; int main() { cout << "Hello, Cyber Security!"; return 0; }
  • #include <iostream> → request a header (handled before compilation)
  • using namespace std; → skip writing std:: everywhere
  • main() → where execution begins; { } → a block; ; → ends statements
  • cout << → send to output; return 0; → normal completion

Compilation pipeline

1 · Source (.cpp)→ 2 · Preprocess→ 3 · Compile→ 4 · Link→ 5 · Executable
❓
Classic exam question: Does the CPU execute cout << "Hello"; directly? No — the CPU runs generated machine instructions, never the C++ text itself.

Input · Process · Output

The simplest execution model: Input data enters → Process transforms it → Output result leaves. cin >> reads into a variable, cout << sends it out. Don't confuse << with "less than" — meaning depends on context.

Identifier rules

  • Starts with a letter or underscore — never a digit (2factor ❌)
  • Then only letters, digits, underscores — no spaces/hyphens (user-name ❌)
  • Keywords like int are reserved (int ❌)

Core data types

TypeStoresExample
intWhole numbers0, 3, -15
float / doubleReal numbers (double = more precision)3.14, 0.75

📏
Don't memorize byte sizes! Use sizeof(int) on your own system — sizes are implementation-dependent. C++ only guarantees minimum ranges.

Declaration vs Initialization vs Assignment

int attempts; // declaration — create it int attempts = 3; // initialization — first value attempts = 4; // assignment — replace later

Scope: a variable declared inside { } is only visible inside its block. Smaller scopes = fewer accidental bugs.

Arithmetic & Precedence

OperatorMeaningExample
+ - * /Add, subtract, multiply, divide8 * 2 → 16
%Remainder (modulus)8 % 3 → 2
1 · ( ) Parentheses→ 2 · * / %→ 3 · + -
int x = 2 + 3 * 4; // 14 (× before +) int y = (2 + 3) * 4; // 20 (parentheses first) int r = 20 - 6 / 2 * 3; // 11 (÷,× left→right, then −)
⚠️
Integer division: 7 / 2 → 3, not 3.5! Both operands are ints, so the fraction is discarded. Need decimals? Use a double operand (7.0 / 2).

Constants: prefer const int MAX = 3; (typed, compiler-checked) over #define MAX 3 (raw text replacement).

🧠 Memory Tricks

  • IPO → Input → Process → Output — like a kitchen: ingredients → cooking → meal.
  • Flowchart shapes → "Old People Drink Tea" — Oval (start/end), Parallelogram (I/O), Diamond (decision), The rectangle... remember Rectangle = process, arrows connect. Oval = ends · Diamond = question · Rectangle = work · Parallelogram = data.
  • Precedence → "PEMDAS-lite": Parentheses → * / % → + −. Same level? Left to right.
  • Integer division → 7 / 2 is 3, not 3.5 — int ÷ int chops the decimal. Want decimals? touch a double.
  • Compilation → "PCL" — Preprocess → Compile → Link → exe.

🎬 Worked Example — Trace the expression

🧩 int result = 10 + 3 * 2; then double d = 7 / 2;
1Look for operators: + and * both present — precedence decides the order, not reading order.
2* beats +: first compute 3 * 2 = 6.
3Then add: 10 + 6 = 16 → result holds 16 (not 26!).
4Next line — integer division: 7 / 2 → both operands are int → result 3 (decimal chopped, never rounded).
5Fix it: double d = 7 / 2; still gives 3! You must touch a double inside the math: 7 / 2.0 or (double)7 / 2 → 3.5.
6Exam habit: circle the operators, mark precedence, evaluate left→right within a level, then check operand types.

⚡ Quick Tips — Week 1

🧠

Trace before running

Predict the output on paper first. If your prediction and the compiler disagree — one of you is wrong, and it's usually you.

🏷️

Names beat letters

failedAttempts beats x. Your future debugger self will thank you.

🧼

Readable = auditable

Clean formatting isn't decoration — in security work, readable code is easier to audit for bugs.

🔁

One change at a time

When debugging, change one thing, recompile, observe. Never change five things at once.

⌨️

Semicolons matter

The #1 beginner error in Week 1: forgetting ;. The compiler will point at the line after your mistake.

📝

Comment the WHY

Good comments explain reasoning (// avoid integer division), not syntax (// add 1).

Question 1

What is the difference between a program and a programming language?

↻ tap to flip
Answer

A program is a specific set of instructions performing a task. A language is the formal notation used to express such instructions.

Question 2

What are the stages between C++ source code and an executable?

↻ tap to flip
Answer

Preprocess → Compile → Link → Executable. The executable contains machine-level instructions the OS can load.

Question 3

Evaluate: int result = 20 - 6 / 2 * 3;

↻ tap to flip
Answer

11. ÷ and × beat −, evaluated left→right: 6/2=3, 3×3=9, 20−9=11.

Question 4

Is user-name a valid C++ identifier?

↻ tap to flip
Answer

No. The hyphen is the subtraction operator. Identifiers allow only letters, digits and underscore.

Question 5

int x = 5; x = x + 2; — final value?

↻ tap to flip
Answer

7. Read old value 5, add 2, store 7 back into x.

Question 6

Why might double beat int for a rate like 0.125?

↻ tap to flip
Answer

int stores only whole numbers; double represents fractional values needed for rates.

Week 3 — Decisions: if, else & Logic

Programs stop being straight lines. A decision picks a branch at run time based on a condition that evaluates to true or false.

❓ Condition→ 🔀 true / false→ ✅ Branch A / B
Relational opsMeaning
== !=equal · not equal (NOT = — that's assignment!)
< > <= >=less · greater · less-or-equal · greater-or-equal
⚠️
= vs ==: single = stores a value; == asks if two values are equal. Using = in an if is a classic bug (and usually a compiler error).

if · if-else · nested · else-if ladder

FormShapeWhen it runs
ifif (cond) { A; }A runs only if cond is true (else: nothing)
if-elseif (cond) A; else B;exactly one branch runs
nestedif (a) { if (b) … }inner runs only if BOTH are true
else-ifif…else if…elsetested top-down; first true wins; else = fallback
💡
Order matters — the "ladder rule": in if (n<0) … else if (n==0) … else … the test you check first can make later tests redundant. Ranges therefore strictest first: else if (score >= 90) before score >= 80.
🪤
Dangling else: an else always binds to the nearest unmatched if. Ambiguous nests → use braces {} so it attaches where you meant.

Logical Operators & Ranges

aba && ba || b!a
TTTTF
TFFTF
FTFTT
FFFFT

Range test: x >= 10 && x <= 90 — both sides must be true. 10 <= x <= 90 does not work in C++ (it evaluates left-to-right as a bool).

Flags: a bool variable that records a yes/no state (bool found = false; … set true when something happens).

Short-circuit: && stops at the first false · || stops at the first true — the right side may never be evaluated.

Validation, Menus, switch & ?:

ToolPurposeCheat
Validation loopRe-ask until input is legalwhile (x < 1 || x > 6)
MenuPresent choices, act on selectionprint options → read choice → if/switch
switchBranch on an int/char valuecase n: … break; (missing break = fall-through!) default:
?:One-line if-else expressioncond ? a : b
char vs stringchars compare with '=='; strings use == via std::string (or strcmp for C-strings)'A' vs "A"
🧠
switch needs break (or return) — without it execution falls through into the next case. switch works on integral types only; conditions/logic → use if/else-if.

🧠 Memory Tricks

  • if = red light test — green: run the block · red: skip past it.
  • else = the other shoe — it only drops when the if didn't.
  • && needs BOTH checks, || needs EITHER — "honey, are you and home?" vs "pizza or burger?"
  • ! = mirror — true becomes false, false becomes true.
  • Strictest first — once a high score matches, lower thresholds can't be reached; ladder keeps order.
  • break = STOP sign — fall-through is the broken sign.
  • = pours, == compares — assign vs ask.
  • ?: = mini if-else — condition ? true-part : false-part.

⚡ Quick Tips — Week 3

✏️

Trace on paper first

Write the input, walk each branch by hand, note which lines run — hand tracing catches ordering bugs.

🧱

Brace every nest

Even single-statement blocks — kills the dangling-else trap and future edit surprises.

🔁

Validation pattern

Read → test range → while invalid → re-prompt. Repeat for every user input.

🎯

Common errors

assignment in condition · missing braces · fall-through switch · wrong comparison · off-by-one range ends.

⌨️

cin leaves the newline

After cin >>, a stray \n can break later getline — clear it if mixing input styles.

🧪

Test the edges

Check boundary values (89/90, 9/10) — conditions usually break at the borders.
