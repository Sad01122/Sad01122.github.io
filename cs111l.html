Program Structure & I/O

#include <iostream> using namespace std; int main() { int age; cout << "Enter your age: "; cin >> age; cout << "You entered: " << age << endl; return 0; }
  • cin >> reads whitespace-separated input; a simple string stops at the first space
  • endl or \n moves to a new line
  • Multiple inputs in one line: cin >> name >> age;
💡
Most common Week-1 compile error: the missing semicolon. The compiler reports the error on the line after your actual mistake — always check the previous line too.

🔍 Debugging — Find the Cause, Not Just the Error

Five-question method:

  1. What did I want the program to do?
  2. What did it actually do?
  3. Is it a compile-time or logical problem?
  4. Which line/expression is most likely responsible?
  5. What one change can I make and test?
Common problemFix

string not recognisedAdd #include <string>
Wrong calculationCheck formula + data types (integer division!)
Record
Debugging record format: Expected → Actual → Suspected cause → Change made → Test result.

🧠 Memory Tricks — Week 01

  • Six steps → 3 think, 3 do: Understand · Plan · Code ‖ Compile · Run & Test · Debug.
  • Type sizes → "CIFDB" — Char 1 · Int 4 · Float 4 · Double 8 · Bool 1 byte (approximate, machine-dependent).
  • Flowchart → code → Oval = int main() start/end · Parallelogram = cin/cout · Rectangle = assignments/math · Diamond = if.
  • Syntax vs logic error → syntax = compiler stops you (red text) · logic = program runs but gives wrong answers (you must test).
  • Debug rule → change one thing at a time, re-run, observe. Two changes = you learn nothing.

🎬 Worked Example — Storage calculator logic

🧩 "How many bytes does a person's record take?"
1Read the task: one int age, one double marks, one char grade — find total bytes.
2Let the machine answer: cout << sizeof(age); → typically 4 — never guess sizes in code.
3Add them: sizeof(age) + sizeof(marks) + sizeof(grade) → 4 + 8 + 1 = 13 bytes.
4Print with labels so output is readable — the lab marks clarity, not just the number.
5Exam twist: ask again for 100 people → multiply by 100 (1,300 bytes ≈ 1.3 KB). Show the reasoning, not just the answer.

Type Conversion & Casting

  • Implicit — automatic, safe widening: double value = number; (int → double)
  • Explicit — programmer forces it with static_cast<>
int obtained = 7, total = 2; // WRONG: 7/2 = 3 (integer division before assignment) // RIGHT: cast one operand first → 3.5 double average = static_cast<double>(obtained) / total; char digit = '5'; int number = digit - '0'; // 5 — char to int trick
❓
Exam trap: changing only the variable type to double is NOT enough — (7 + 8 + 10) / 3 still divides as integers first. You must use / 3.0.

🧠 Memory Tricks — Week 02

  • Cast it loud → to kill integer division, make one operand a double: static_cast<double>(a) / b. Casting AFTER dividing is too late — the decimal is already chopped.
  • Digit trick → '7' - '0' = 7. Char digits are consecutive in ASCII, so subtracting '0' converts them.
  • Compound ops → x += 5 ≡ x = x + 5. Same for -= *= /= %= — shorter, fewer typos.
  • <iomanip> trio → Width (setw) · Alignment (left/right) · Precision (fixed + setprecision). "W-A-P" fixes any table layout.
  • Modulus in real life → n % 2 == 0 means even · n % 60 converts seconds → minutes.

🎬 Worked Example — Percentage table without wrong decimals

🧩 The classic lab bug: 78.5% prints as 78
1Bug: double pct = marks * 100 / total; with ints marks=314, total=400 — 314 * 100 = 31400, then 31400 / 400 = 78… but if inputs are int everywhere, watch the order.
2Real trap: total * 100 can overflow a small int in other tasks — do the division first or cast early: static_cast<double>(marks) / total * 100.
3Force decimals: cout << fixed << setprecision(2) << pct; → 78.50.
4Align the columns: cout << left << setw(12) << name << right << setw(8) << pct << '%'.
5Result: 
Name         Marks   %
Ali           314   78.50
Sara          361   90.25
Same numbers — but now it looks like a mark sheet.

⚡ Quick Tips — Week 02

🎯

Cast one operand

For decimal division, cast one side only: static_cast<double>(a) / b.

📊

setw for tables

Never hand-align columns with spaces — setw() survives names of any length.

🧮

% means remainder

Great for even/odd checks (n % 2 == 0) and digit extraction. Only works on integers.

⏱️

Trace compounds

After every +=/-=, write the new value down. Half of lab marks are in the dry run.

📎

Include iomanip

setw, fixed, setprecision all live in <iomanip> — missing it = compile error.

✅

boolalpha matters

Passing status must print true/false, not 1/0 — that's a marking criterion.

🖼️ See It: Decision Structures

if / else — one question, two paths, one exit
Nested decisions — the two-gate idea (pass Gate 1 before Gate 2 is even checked)

if / else-if Ladder, Validation & switch

// else-if ladder: first TRUE condition wins, the rest are skipped if (marks >= 80) cout << "A"; else if (marks >= 70) cout << "B"; // marks = 74 → prints B, stops else if (marks >= 60) cout << "C"; else cout << "Needs improvement"; // Input validation — check BEFORE using the value if (marks >= 0 && marks <= 100) cout << "Valid"; else cout << "Invalid"; // switch — one variable vs several fixed constants switch (choice) { case 1: cout << "Add record"; break; // no break = FALL-THROUGH! case 2: cout << "View record"; break; case 3: cout << "Exit"; break; default: cout << "Invalid choice"; // catches everything else }

Flags — remembering status

bool validInput = true; // flag starts optimistic if (age < 0 || age > 120) validInput = false; // something went wrong → drop the flag if (validInput) cout << "Accepted"; else cout << "Rejected";
💡
Validation types to memorise: range (0–100) · positive (> 0) · allowed choice (1–4) · character type (isalpha) · non-empty (!name.empty()).

🧠 Memory Tricks — Week 03

  • = vs == → one = puts a value in the box · two == asks what's in the box. "Single equals stores, double equals questions."
  • cctype family → "is" + name: isAlpha · isDigit · isAlnum (alpha+digit) · isSpace. If none → special character.
  • else-if ladder → highest grade first, descending. First TRUE wins — everything after is skipped.
  • Two gates → nested if = Gate 1 (age) then Gate 2 (ID). You can never reach Gate 2 without passing Gate 1.
  • switch needs break → without it, cases fall through like dominoes. default = the safety net.
  • Flags → a sticky note: true = "still good", false = "something failed". Check it after all tests.
  • getline after cin → always cin.ignore() first, or getline reads the empty leftover newline.

🎬 Worked Example — Grade calculator with validation

🧩 Marks in, grade out — with the 0–100 safety check
1Get input first: int marks; cin >> marks; — declare close to where you use it.
2Validate BEFORE logic: if (marks < 0 || marks > 100) → print error and return 0; (exit early, no invalid data reaches the ladder).
3Build the ladder high → low: >= 80 → A · >= 70 → B · >= 60 → C · >= 50 → D · else → F.
4Trace it: marks = 74 → 74≥80 false → 74≥70 true → prints "B", skips the rest. Ladder order matters — reversed order would wrongly print A.
5Test edges: 100 → A · 0 → F · −1 → invalid · 101 → invalid. Boundary cases are exactly what graders try.

⚡ Quick Tips — Week 03

🎯

Validate early

Reject bad input at the door (return 0;) — never let invalid data flow into calculations.

🧪

Test boundaries

For 0–100 ranges always try −1, 0, 100, 101. Four lines of testing catches most logic bugs.

🔀

break in switch

Every case except the last needs break — fall-through is a classic exam bug to spot.

📝

Trace on paper

Exam tracing questions reward the table, not just the answer. One row per statement.

⌨️

getline vs cin

cin >> stops at spaces; getline takes the whole line. Pick based on the prompt.

🚩

Flag pattern

bool ok = true; → checks may set it false → one final if (ok) decides. Clean and readable.
